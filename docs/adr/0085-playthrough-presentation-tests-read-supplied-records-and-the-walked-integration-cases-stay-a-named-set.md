# Playthrough presentation tests read supplied records, and the walked integration cases stay a named set

The playthrough UI suite walked a real progression for every case: a presentation assertion about the curves plot's selection, the historical inspection's board read, or the note's rendering paid for a full `devRunPlaythrough` walk first. Measured before choosing (issue #510's own rule), three multi-day pushing-policy journeys dominated — ~310 of the file's ~319 test seconds — and every presentation case repeated a smaller walk whose balance outcomes the case never asserted. The deeper failure was ownership: balance expectations (which claim the curve banks at a depth, which day a journey completes) lived inside UI cases, so a shipped-figures change would have surfaced as unrelated presentation failures instead of at the engine and calibration assertions that own those figures.

## Decision

- **Presentation cases read supplied records.** A presentation case declares the facts it needs — plotted samples, stamped decisions, historical boards, recovery marks, the note's figures — through `src/ui/testing/supplied-playthrough.ts` and brings the record in through the real artifact boundary. Snapshots capture through the same shape a walk's snap performs (clone, rate-sync on the preview basis, sorted voices, figures off the same clone, deep-frozen), so the presentation reads structures indistinguishable from a recorded run's, including the boundary shapes a given walk may never produce on schedule: tied clocks, era-local events, and explicitly unreached (null) marks. Each case constructs its own record — no shared fixture store, no stale caches (the non-goal holds).
- **A supplied record is honest about its origin and is never reachability evidence.** The carried source names `supplied-constructed`, so no surface can present one as a current-engine walk: the library marks the entry imported, the note rides the "Imported · " prefix, and the curves provenance shows "≠ current". Nothing in a supplied-record case may stand in for "the engine reaches this".
- **The walked integration cases are a named set.** The file's header names the owners: reachability (the prompt door's honest zero, the pushing policy's worthwhile-prestige journey, the explicit incomplete outcome of an unreached claim target), and command-to-engine behavior (recipe composition and rejection, schedule and calendar arithmetic, reproducibility and provenance, the record's event shapes with the walk's isolation from the live state and ordinary save, budget exhaustion, the frontier cap and World placement rules, the checkpoint preset install, the panel and terminal wiring). Balance figures do not pin these cases: they assert reachability and record-derived structure (the frontier stands at the claims' sum; the stop reason names the record's own day and frontier), never a shipped bank amount or completion day.
- **Balance outcomes are engine and calibration verification.** The frontier curve's figures pin in `src/engine/world.test.ts`; the walked checkpoint banks and their days pin in `src/engine/progression-presets.test.ts`; the pace windows pin in the tools' declared evaluation matrices. A UI case may reference a shipped constant (`BALANCE.world.claimBase`) to stay valid while the engine's pins move — it never copies the figure.

## Consequences

- **The demonstration is behavioral, not a test count.** A controlled `claimBase` 2→3 change leaves the presentation file green (59/59) while the engine's curve pins and the walked-bank pin fail by name (issue #510's completion record carries the run).
- **A supplied record can drift from the walk's capture shape.** The helper mirrors the snap shape rather than calling it, so a change to the walk's capture must be mirrored by hand; the engine retention suite (`playthrough-retention.test.ts`) owns the walked shape itself, and the presentation cases would keep passing — correctly, since they test the presentation's reads, not the capture.
- **Long-walk evidence is paid once, where it is evidence.** The worthwhile-prestige journey remains one real 12-day walk; the dropped half-recovered journey's guarantees re-homed to their owners — the note's unreached rendering to the supplied-record readout cases, the walk's explicit-null marks to the budget-exit variants that already walked them cheaply. The removed walks are redistributed coverage, not a speedup claim.
