# Restructure the console around the focus banner and the Focus control sheet

The instrument map's focus-surfaces review ([#242](https://github.com/wvanderen/flowsynth/issues/242), ticket [#249](https://github.com/wvanderen/flowsynth/issues/249), resolved on the focus-surfaces prototype) found the console's tiles-and-launcher furniture fighting the instrument standards: generic rounded cards, hidden reads, a launcher standing in for navigation. The build-out grilling ([#255](https://github.com/wvanderen/flowsynth/issues/255), four prototype iterations) settled the replacement. This ADR records the console's new shape; the apps-off-the-board placement (ADR-0012) stands, ADR-0033's launcher and its Goals-state read are amended, and the presentation follows the ruled folio confirmed in #249.

## Decision

- **The console's face is the focus banner**: a figure-led strip over the board's head reading the session state — the clock beside the main switch, habit and plan reads, and three goal-progress bars that bias in-progress goals (nearest complete first, completed fill the remaining slots) with a `+N` overflow count chip. Reads go live during flow: the clock reads elapsed, bars fill, the habit name reads the active habit. *Amended by issue #331 (2026-10-13 play-feedback interview): the habit read leaves the banner for the session group itself — habit, planned duration, and Start as one contiguous group at every width, the habit name the direct change door into the HABIT face (upgrade mode only; a running session's name is a plain read), and the banner carries the goal bars alone.*
- **The Focus control sheet** unifies Plan, Habit, Goals, and History in one frame behind the banner, carrying the enter confirmation. The flow-mode rule is *read live, capture freely, mutate nothing*: PLAN becomes the running read (live elapsed, End flow mirroring the main switch, targets visibly disabled); HABIT opens on a figure-led list whose rows drill into development detail, with add and log as on-demand action-button forms, locked during flow; GOALS shows live progress with create and delete locked during flow; HISTORY is unaffected.
- **Notes leaves the console** for its own launcher entry and a tabbed CAPTURE | LOGGED sheet in the Focus frame, opening on CAPTURE; the live habit tag chip rides the composer during flow (upgrade-mode notes untagged). The sheet requires no Note Generator disclosure (amended during PR #307 review on 2026-10-09). The larger Notes rework remains a future milestone.
- **The phone banner is launchers only**: the nav row drops the habit name and goal bars entirely for the clock, the switch, and bare uncarded icons — focus, Notes, Settings — with the inset marker as the sheet-open state. The compact launcher retires; this amends ADR-0033, whose Goals-state read survives on desktop only. *Amended by issue #331: the nav row carries the session group — the habit name rides beside the clock and switch at every width; only the goal bars stay docked out. The one-click rule rides with the group: habit chosen and plan armed, Start commits in one activation without opening the sheet, the confirmation preference notwithstanding; every other shape keeps #280's PLAN-face confirmation.*
- **The dev console wears a drag handle**: a pointer-capture grip, clamped to the stage; arrow-key nudging while focused is an implementation nicety, not a blocker.
- **Edge states**: no plan ever set with confirmation off → instant-start falls back open-ended; zero habits → no blocking, the select reads "none selected"; every goal complete → full bars hold in the charge green until slots are replaced.

## Consequences

- ADR-0033's compact launcher and its phone-side habit/goal reads retire; ADR-0028's session-controls-only phone nav keeps the clock and switch it named.
- The console tiles and their popovers, as furniture, retire without save impact — the banner's edge states derive from existing session state, and no new persisted key is introduced.
- The instrument standards (#243) govern the banner's and sheet's presentation; the resolved prose cuts (flow-mode paragraph, goals explainer, manual-log line as tooltip) land with implementation.

## Session surface amendment — PR #337 review

The logo, habit, and timer share one native Focus button at desktop and phone widths. One hover boundary, keyboard outline, and sheet-open marker cover the entire read area and stop before the session action controls. Activation opens PLAN; HABIT selection and editing live inside the sheet. During flow the button opens the read-only controls. Start/Exit and Pause/Resume keep their own gestures, and the sheet is a sibling of the button so its interactions never trigger the door. The separate phone Focus icon retires. The habit name yields width to the timer and actions; inner gaps tighten on phone and redundant child padding retires.

## Notes modal amendment — issue #332 (2026-10-13 play-feedback interview)

Notes leaves the shared anchored frame this ADR gave it: its launcher opens a modal composition in the dialog layer — centered on desktop and phone — independent of the clock or launcher location, so its placement is predictable from the door. The composition opens on CAPTURE and retains LOGGED; capture and live habit tagging are unchanged. Notes stays usable during flow while the modal blocks the board. The dialog manages keyboard focus within itself and returns it to the invoking control on dismissal; ✕, Escape (from the composer included), and backdrop dismissal serve keyboard and touch. Everything else here stands — the Focus control sheet keeps the anchored frame.

## Interface refinement amendment — 2026-10-20

The approved interface-refinement review preserves the compact one-row header and existing Focus identity, centers the session console on desktop, and embeds the independent Notes icon touch surface beside the Focus door inside its dark well. Notes is a sibling control, never nested inside the Focus button. Settings stays at the header edge; Goals gets no independent header button. Habit/state reflows below the clock on narrow screens. Pause/Resume and the main action keep fixed dimensions and remain visible across modes, with Pause disabled where unavailable. Breather’s caption is simply “Breather”.
