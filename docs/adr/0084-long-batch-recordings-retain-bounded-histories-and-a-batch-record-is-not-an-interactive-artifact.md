# Long batch recordings retain bounded histories, and a batch record is not an interactive artifact

The century tier's long walks — the supplied-board fixture above all — retained two unbounded structures for the length of a recording: the allocation solve memo's per-state entry map, which grew with every changed fingerprint on the one live walk state (~300 MB per fixture day observed, multiple gigabytes and exhaustion at the full declared stop), and the run record's exact historical snapshots, one cloned frozen game state per plotted sample, session boundary, and stamped decision. Profiling before choosing (#509's own rule) identified both, and separately: the memo dominated the memory curve, the snapshots dominated the retained-record growth.

## Decision

- **The allocation memo's per-state retention is bounded (8 entries), recency-refreshed.** The memo's documented purpose — consecutive ticks and a render's twin passes serving one solve, plus the solve's own write-back pair — reads only recent entries, so retention keeps those and evicts the oldest. A fingerprint recurrence deeper than the bound re-solves to the identical result: the solver is deterministic given its inputs, and the one way a re-solve can differ is the wall-clock valve tripping where the original solve did not. That surface is counted, not presumed away: the solver's budget outcomes (solves, uncertified passes, node-cap and deadline trips) are module stats any profile can read.
- **A batch walk may declare bounded historical retention.** `runPlaythrough` accepts a retention mode; bounded walks capture, at the moment of each snapshot, the figures every report read consumes — balances, the maxima the numeric read reports, the whole-state finite verdict, and the save seam's serialized round-trip verdicts on the report stride — and drop the board. Complete retention (the default, and every interactive path) keeps every snapshot's whole frozen state exactly as before, with the captured figures computed alongside from the same clone.
- **A bounded record refuses every interactive surface, by name.** Historical inspection, artifact export, and artifact import all reject a bounded record with a named error: it is a batch summary, never a complete interactive artifact wearing one's identity. The readers that genuinely need historical boards (the later-era probe boundary, artifact export) assert complete retention through one named narrow.
- **The century recorder tier records bounded.** Its rows read captured figures only, so the fixture walks' memory stops growing with the board. The later-era tier keeps complete records because its route probes replay from historical boards — the boundary is per-tier by need, not global by fashion.

## Consequences

- **Equivalence is verified, not assumed.** On identical inputs the retentions produce identical rows wherever every solve certified; the profiler's differential fails on disagreement without uncertified solves, and records — never hides — disagreement under deadline trips, which is the valve's timing-dependent incumbent, not a deterministic divergence. Suite regressions pin row equality on certified walks for fresh starts and continuations alike.
- **A bounded record cannot be re-read as a board later.** That is the trade: inspection of a batch walk's history requires a complete record. The evidence a report needs survives the drop by construction (capture-time verdicts), so nothing report-shaped is lost — only the boards are.
- **The profiler is the measurement, and the measurement is reproducible.** One entry point runs the identical fixture workload through both retentions, each in its own process (peak memory attributed per run, never polluted by a sibling's retained record), separates simulation/allocation, capture, serialization, and report costs, and publishes the comparison with its limitations.
- **Balance is untouched.** The bound changes when a solve re-runs, never what a solve computes; where every solve certified, recorded outcomes are proven identical.
