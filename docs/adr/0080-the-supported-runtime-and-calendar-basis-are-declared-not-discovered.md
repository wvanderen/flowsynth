# The supported runtime and calendar basis are declared, not discovered

Checks and recordings ran on whatever Node the shell resolved, and the divergence between that runtime and CI's was debugged repeatedly instead of declared once. The #491 evidence round records the pattern at its worst: a full-suite failure whose cause (Node 26's webstorage global versus the UI harness's storage) was repaired with a repo `.npmrc` file-backed-storage workaround, then patched per-session with a hand-built `PATH=/…/node/22.23.4/bin:$PATH` override — a private incantation each agent reconstructed from old evidence READMEs. Separately, gameplay's calendar basis (goal occurrence days and playthrough schedule days follow the host's local calendar) kept being rediscovered as "UTC versus local" divergence rather than read off a declaration (issue #505, 2026-11-04).

## Decision

- **One runtime declaration.** `.node-version` pins the CI-compatible supported runtime as one concrete semver (`22.23.4`), and everything consumes that file: CI's `actions/setup-node` installs exactly it (`node-version-file`), version managers select it from the same file (idiomatic version files), and the preflight and suite guard read it for enforcement. No second version figure lives anywhere — a runtime bump changes one line.
- **The npm scripts select the runtime themselves.** `npm test`, `npm run check`, `npm run dev`, `npm run build`, and `npm run test:calendar` run through `tools/run-supported.mjs`, which compares the starting runtime against the declaration and re-execs the entry under the declared binary — found via `FLOWSYNTH_NODE` or the version managers' standard install layouts (mise, nvm, fnm, volta, asdf, n), verified to actually report the declared version before use. Ordinary checks never depend on which node started them; no agent reconstructs a private PATH override.
- **A cheap gate before expensive work.** `npm run preflight` reports the declared and effective runtime, the host's calendar zone, and the UI harness's storage capability (happy-dom's localStorage probed the way the fixtures use it), and refuses with per-manager fix lines. The suite's `globalSetup` guard (`tools/dev/runtime-guard.mjs`) repeats the check, so a bare `npx vitest` on the wrong runtime fails in milliseconds instead of twenty-eight fixture failures deep. CI runs the preflight after install and before any check.
- **The calendar basis is declared.** Gameplay reads the host's local calendar — the engine's own goal-occurrence rule (the goals primitives' local day and Monday starts) and the playthrough schedule's day arithmetic (`setDate` strides over local days, DST transitions included) — and that basis is stated in the preflight's report, the glossary, and `src/engine/calendar.test.ts`. No runtime or environment flag redirects it.
- **Calendar-sensitive regressions run under both declared bases.** `npm run test:calendar` executes `src/engine/calendar.test.ts` and `src/engine/goals.test.ts` under UTC and a DST-observing zone (`America/Chicago`), targeted — two files, twice — never a duplicated full suite. The cases derive expectations from raw UTC-offset arithmetic, an independent construction, so the day primitives can never disagree with themselves without failing; the fall-back day's two midnight instants are pinned to the engine's pick (the earliest).
- **Recordings name their environment.** Every new balance recording (the gated report writers and the `record-*.mjs` tiers) writes `recordingEnvironment` — `{ node, timeZone, utcOffsetMinutes }` — beside its commit and source fingerprint. Recordings made before this metadata carry no field and stay identifiable as legacy; no reader fabricates a value for them.

## Consequences

- **The `.npmrc` webstorage workaround is deleted, not supported.** The file-backed store existed to make Node 26 tolerate the UI harness; with the runtime pinned and enforced, no compatibility workaround remains. If a future runtime genuinely needs a shim, it gets a documented, named purpose in a decision — never a silent `.npmrc` comment.
- **Bumping the runtime is one line plus a full-suite pass.** Change `.node-version`, run the suite through the scripts; CI and local selection follow. The exact pin means parity is bit-for-bit — local and CI run the same build of the same runtime.
- **The pinned zone pair can grow but not shrink.** A new host calendar concern adds a leg to `CALENDAR_ZONES`; the UTC and DST legs stay.
- **Preflight refusals are the documented failure mode.** An unsupported environment is refused before checks, recordings, and evidence — the refusal names the fix, so the old evidence-README archaeology has nothing left to find.
