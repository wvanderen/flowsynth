# The later-era evaluation records as one resumable job

The later-era evaluation recorded through all-or-nothing CLI invocations: a slice command ran eight seed walks in one process and wrote its slice file only at the end, and composition ran the probe walk and every route continuation hidden inside itself. An interruption — a killed shell, an ordinary tool-call timeout — destroyed the in-flight slice's work entirely; #491's six-slice split bounded a loss to one slice, not to one walk. The agent running the multi-hour evaluation had no supported way to launch, observe, resume, or be told of completion, so each session improvised shell detachment and sleep/poll loops (issue #507, 2026-11-05).

## Decision

- **One supported interface.** The later-era recorder exposes `run` (launch or resume — the whole declared evaluation, or one slice's units), `status` (completed/remaining units, failures, elapsed time, worker memory, log and status locations), and `compose` (verify and publish the report). The smoke tier drives the same pipeline on bounded walks. No second recorder path exists for this evaluation.
- **Completed work is persisted atomically, per unit.** Every unit — one seed's walk, the probe walk, one route order's forward continuation — is written by its worker through serialize → exclusive temporary → fsync → rename, so a kill at any point leaves the previous bytes or the complete new ones, never a partial write that could pass for completed evidence. The supervisor never writes evidence.
- **Reuse is decided by input identity, not by presence.** A stored unit is reused exactly when its identity — the compiled engine and runner source, the full recipe (seed, schedule shape, calendar basis, budgets, stops), the evaluation-logic version, the allocation solver's declared budget, and the runtime — equals what this checkout would run now. Nothing report-shaped appears in the identity: a report-format change never discards completed evidence, while any simulation change invalidates exactly the units it touches (a forward also carries its parent walk's identity). Corrupt or duplicate-shaped evidence is rejected — its bytes preserved under `logs/corrupt/` for forensics — and re-executed.
- **Workers are separate processes with an explicit resource budget.** Bounded concurrency (`--jobs`) and a per-worker V8 heap cap (`--worker-mb`) are recorded in the durable status beside each worker's elapsed time and peak memory. Completion, failure (a unit fails alone; the job records the diagnostic and ends `failed`), cancellation (SIGTERM/SIGINT stops workers and records `cancelled` with the notification still firing), and restart (a stale lock is taken over; a killed supervisor's registered workers finish before any plan rewrite, compile, temporary cleanup, or replacement worker) are defined behaviors. Workers wait for an IPC start authorization sent only after their pid lease is durable. Recovery counts no surviving worker as missing work; its completed unit, elapsed time, and memory evidence are reused. Cancelling recovery records `cancelled` and notifies, but leaves the old workers registered to finish rather than signalling a potentially recycled pid.
- **The agent never keeps a shell wait alive.** `run --detach` validates everything cheap, spawns a detached supervisor, and returns once the durable status names a live pid; `--notify <command>` runs exactly once at the terminal state with the job directory, final status word, and status file path in its environment. Single-flight supervision refuses a second supervisor on a live job by name. Detached preflight compiles in disposable storage; only the lock holder can compile into the job directory. Relative `--dir` paths are normalized before compilation or handoff.
- **Composition runs no walks.** The route probes — previously executed hidden inside compose — are persisted work units; compose verifies completeness and provenance (fingerprint byte-for-byte, every unit's full identity matching current inputs and its recording commit an ancestor of HEAD, the exact seed and affordable-order matrices complete without duplicates, each forward present and advancing) and publishes the report. The probe evidence composes from units the job's workers recorded, under `routeProbeRecordingEnvironment` as before.
- **One recording boundary.** Persistence, validity decisions, and job status live in one module (`tools/dev/job-recorder.mjs`), the recording domain (identity, execution, publication, verification) in the compiled recording module and its adapter half, and the static gate checks the plain-`.mjs` boundary with the recorder CLIs. The CLI and the verification exercise the same functions.

## Consequences

- **A changed engine re-records everything, honestly.** The fingerprint rides every unit's identity, so a source change invalidates the whole matrix at the next `run` — staleness is refused by composition, never accepted; the recovery is the resumable job itself, not a workaround.
- **A forward's inputs are rebuilt, not inherited.** Resume re-derives descriptors from the verified stored probe walk using the current builder, so a changed forward-only budget invalidates its evidence even when the walk remains reusable.
- **Published identity provenance is required.** `unitProvenance` now retains each original worker identity beside its original commit and environment. Identity-less publications are refused, not upgraded by inventing current identities: re-publish from the original verified unit files, or re-record when those files are unavailable. The #507 artifacts were migrated from their 69 preserved units without changing any row, bank, measurement commit, or environment. Stop any workers from the pre-lease recorder before upgrading that working directory; completed pre-lease units remain reusable.
- **The job directory is working state, not evidence.** `.recording/` stays out of the checkout; the committed evidence remains the published slices, the probe file, and the composed report, each carrying per-unit provenance (`unitProvenance`) beside the slice-level commit and environment.
- **The century recorder keeps its existing path.** Adoption there is a deliberate later step; the job boundary itself is recorder-agnostic.
- **The later-era evaluation's figures still belong to #491's scope decision.** This decision changes how the evaluation runs and how its evidence survives; it changes no declared seed, budget, window, or verdict.
