# The developer controls' audit (issue #466)

The playtesting suite's foundation (#465): which existing development tools remain trustworthy. Every console control a `?dev=1` boot exposes, with its prerequisites, actual effects, save behavior, and its retain/repair/replace/retire disposition. The parent spec's one-place rules and ADR-0077's two-tier split (live-save quick grants vs. isolated in-memory evidence setups) govern the dispositions; nothing here changes those semantics.

All controls live behind the dev panel (`src/ui/render.ts` `renderDev`) and the app methods it wires (`src/ui/app.ts`), reachable only on a dev boot: the panel renders for `?dev=1` alone, `window.__flowsynth` is exposed on dev boots only, and — since this audit's repairs — every helper method gates itself on `this.dev`, so a normal instrument ignores the whole family even if a handle ever leaked.

## Repairs made

1. **`+100ν` now saves.** Before the repair the grant mutated memory only; on an upgrade-mode tab — the grant's main use — nothing ever auto-saved, so a reload silently lost it. The quick grants' documented tier is the live save; now it behaves as advertised (ADR-0077's two-tier split is preserved: the grant writes the ordinary slot at once, the Focus scenario never does).
2. **`World era` requires upgrade mode.** Before the repair the grant force-switched `mode` to upgrade over any live phase, orphaning the session (or breather) in memory *and* in the saved slot — the phantom then survived reloads, and `endSession` answered "No session is running." while the state carried one. The grant now refuses with a named message and leaves the running phase and the save untouched.
3. **Uniform dev gating.** `devFocusScenario` and the board already gated on `this.dev`; the quick controls now do too, and `devToTarget` names its failed prerequisite precisely (clock outside flow, target inside flow). A normal boot ignores every helper — pinned by one case, "a normal instrument ignores every dev helper".
